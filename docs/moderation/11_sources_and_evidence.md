## 2. Conflicts and how they were resolved

### C01: decision endpoint versus generic chat examples

The model listing, current Decisions guide and endpoint reference describe typed decisions. Generic chat-completion documentation and autogenerated Hugging Face deployment tabs do not establish compatibility with that endpoint. The integration proposal therefore uses the explicit Decisions contract.

### C02: current audio/video support versus older indexed descriptions

Current documentation takes precedence over older indexed descriptions. The dated modality distinction is recorded in [02](02_clef_omni_research.md); actual adapter activation still needs contract evidence from [04](04_openrouter_decisions_integration.md).

### C03: advertised latency

S06 reports a much smaller text timing than S07; S01's opened aggregate P50 differed from an indexed result. These are different/dynamic measurements with unclear workload equivalence. [02](02_clef_omni_research.md) preserves the distinction. No value is promoted into a measured project latency or a hard service guarantee.

### C04: context size and truncation

See [02](02_clef_omni_research.md) for model-specific context claims. The decision here is to verify complete target coverage experimentally instead of deriving it from advertised capacity or another model's warning.

### C05: privacy summaries

OpenRouter's provider-logging page contains broader/older wording than the specific ZDR/routing documentation. Use endpoint-specific policy and actual request/account settings for provisioning. This research makes no zero-retention, regional-residency or compliance certification.
