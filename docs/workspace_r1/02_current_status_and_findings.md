## Flags and compatibility

Workspaces graduated on 2026-10-18 (SPA `692e56bb`): the `VITE_FEATURE_WORKSPACES_ENABLED` flag and its reader were removed, the full R1 UI is always on, and workspaces never became a plan permission. The [Sidebar](/home/andres/WebstormProjects/magic-worlds/src/ui/components/Sidebar.tsx) shows Library to every signed-in user. The provider still performs capabilities → GET /workspaces before private loading, and private requests still carry an owned selector. Before graduation, the flag-`false` state hid Library, switcher, collection/copy/create-workspace surfaces; it never disabled workspace isolation.

The capability response remains `{workspace_r1:true, contract_version:1, schema_revision:"2026_10_workspace_r1"}`. The current canonical BFF schema is the revision named by `CONTENT_SCHEMA_REVISION` in the BFF bootstrap (`2026_10_db_refactor` at the 2026-10-26 docs cleanup; a running database is not asserted here). The capability marker is a stable compatibility contract; it must not track every later database revision. Strict bootstrap verifies the actual canonical schema independently.

The workspace cutover now derives its target from frozen `migrations/2026_10_workspace_r1.sql`, not the evolving `db.sql`. It verifies supported later revisions, including the current bootstrap revision, as `superseded` without replaying R1. This verification is not an upgrade from R1 through later migrations; consult the [database guide](/home/andres/PycharmProjects/magic-worlds-api/docs/database.md) and the BFF [Fish Audio guide](/home/andres/PycharmProjects/magic-worlds-api/docs/fish_audio.md) for the intended build/schema chain. Unknown/unsupported schema states still stop. Follow the release environment's verified migration chain; don't run an old revision blindly against a newer schema.

The cutover tooling and its runbook were removed (BFF `fceaead`, 2026-10-26); see [W-01/W-02](04_gaps_and_priorities.md).

Decide whether an origin-aware preview/action is required; existing audio can remain account-level.
3. **Source-confirmed integrity gaps (runtime reproductions still needed):** current `db.sql` defines `tb_card.card_type` as `(character, world, adventure_template, item)` but draft/version child enums as `(character, world, item)` under the `(card_id, card_type)` FKs `fk_card_draft_card_type`/`fk_card_version_card` → `uq_tb_card_id_type`; a 2026-10-12 local item-draft insert failed with ERROR 1452 and item draft/version routes are reachable (W-03). In [models.py](/home/andres/PycharmProjects/magic-worlds-api/src/database/mysql/models.py), `ImageAssetModel.create_asset` still accepts only `fal` parents even though image jobs allow OpenRouter (W-04a); `_require_unreferenced_media_asset` scans card/activity/receipt/card-generation stores but omits assistant output snapshots (W-04b); `TtsAssetModel.mark_deleted` still updates without a reference check (W-04c; latent: no current route or caller). Unbound card-assistant creation (`_apply_card_assistant_target`) inserts through `_create_body_card_with_cursor` without `_clear_other_default_personas_with_cursor`, so an assistant-created default persona does not clear other workspace defaults (W-04d; source-confirmed mechanism, runtime reproduction needed). These are existing cross-feature defects, not new R1 implementation work. Track and reproduce each before selecting a repair/migration; do not treat a dated full-suite pass as closure.
4. **Representative operation volume:** earlier 35,000-card testing did not seed every assistant, TTS/theme-song and retained execution path. Those paths have integration coverage; environment volume/migration timings still need measurement.
5. **Deferred product scope:** account-wide cross-workspace search, nested/smart collections, shared human workspaces and bundle transfer remain future design work. Flat personal workspaces and independent copying are the implemented R1 boundary.
