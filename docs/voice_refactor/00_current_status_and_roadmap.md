**Resolved cross-feature blocker (V-10).** BFF commit `2c2973d` lets chat turns drop the read-card planner's `mw_read_card` call previews. This applies to the `narrative` contract only, with strict shape, identity, order and count rules. Any other tool is still refused. The deployed smoke passed with this build. The paragraph below is the original analysis.

**Original analysis (superseded):** the later 15 §13 report attributes narration-smoke failure to `mw_read_card` planner calls entering the public narrative stream. Current BFF `conversation_execution.py` restricts its tool collector to `mw_emit_turn_metadata`, while `character_chat.v2.json` includes `mw_read_card`. The reported upstream schema-only tool forwarding is a conversation execution contract issue; this review confirms the BFF graph/allow-list mismatch and records the smoke report, without a new live reproduction. Resolve internal-versus-public tool streaming, then repeat chat completion and narration smoke. Do not broaden the public allow-list without a validated transport contract.

The smoke changed a test account's creation time to pass Free eligibility. That makes the flow reproducible with an eligible test account; it does not validate naturally aging accounts or authorize bypassing production eligibility.

Current latency telemetry already includes client `vad.speech_end_lag_ms` (VAD hangover, hashing and ready-queue delay) and server `voice_first_assistant_audio.user_stop_ttfb_ms`, plus admission/first-delta/first-sentence events. See [speechEndLag.ts](/home/andres/WebstormProjects/magic-worlds/src/features/interaction/audio/speechEndLag.ts) and [engine.py](/home/andres/PycharmProjects/magic-worlds-api/src/services/voice_orchestration/engine.py). The server metric combines client lag with server route/engine time; it does not prove the browser's first audible sample and is not a full network/playback measurement. Remaining work extends and samples this instrumentation; it does not start from zero telemetry.
